# 如何在Antigravity中使用Skills

技能是扩展 Agent 能力的开放标准。一个“技能”就是一个文件夹，其中包含一个 `SKILL.md` 文件，里面记录了 Agent 在执行特定任务时可以遵循的指令。

## 什么是技能？

技能是可重用的知识包，用于扩展 Agent 的功能边界。每个技能包含：

* **核心指令**：关于如何处理特定类型任务的方法论
* **最佳实践**：需要遵循的规范和约定
* **可选脚本与资源**：Agent 可以调用的辅助工具

当你开始对话时，Agent 会看到一份包含名称和描述的可用技能列表。如果某个技能看起来与你的任务相关，Agent 就会读取完整的指令并按照要求执行。

## 技能存放位置

Antigravity 支持两种类型的技能：

| 位置                                               | 作用域                          |
| :------------------------------------------------- | :------------------------------ |
| `<workspace-root>/.agent/skills/<skill-folder>/` | 工作区特定 (Workspace-specific) |
| `~/.gemini/antigravity/skills/<skill-folder>/`   | 全局 (Global, 所有工作区)       |

**工作区技能** 非常适合特定项目的流程，例如团队的部署逻辑或测试规范。

**全局技能** 可以在你所有的项目中使用。适用于个人工具函数或你希望随处可用的通用工具。

## 创建技能

创建一个技能的步骤：

1. 在上述任一技能目录下创建一个文件夹。
2. 在该文件夹内添加一个 `SKILL.md` 文件。

```text
.agent/skills/
└─── my-skill/
    └─── SKILL.md
```

每个技能都需要一个带有 YAML 前置元数据（frontmatter）的 `SKILL.md` 文件：

```markdown
---
name: my-skill
description: 帮助处理特定任务。当需要做 X 或 Y 时使用。
---

# 我的技能 (My Skill)

此处填写给 Agent 的详细指令。

## 何时使用此技能

- 当...时使用
- 本技能有助于...

## 如何使用

Agent 应该遵循的步骤指南、约定和模式。
```

### 前置元数据 (Frontmatter) 字段

| 字段            | 必填 | 描述                                                                     |
| :-------------- | :--- | :----------------------------------------------------------------------- |
| `name`        | 否   | 技能的唯一标识符（小写，空格用连字符代替）。如果未提供，默认为文件夹名。 |
| `description` | 是   | 清楚地说明技能的作用及其使用场景。这是 Agent 决定是否应用该技能的依据。  |

**提示**：建议使用第三人称编写描述，并包含有助于 Agent 识别相关性的关键词。例如：“使用 pytest 规范为 Python 代码生成单元测试。”

## 技能文件夹结构

虽然 `SKILL.md` 是唯一必需的文件，但你也可以包含其他资源：

```text
.agent/skills/my-skill/
├─── SKILL.md       # 核心指令 (必需)
├─── scripts/       # 辅助脚本 (可选)
├─── examples/      # 参考实现 (可选)
└─── resources/     # 模板及其他资产 (可选)
```

Agent 在遵循技能指令时可以读取这些文件。

## Agent 如何使用技能

技能遵循 **渐进式披露 (Progressive Disclosure)** 模式：

1. **发现 (Discovery)**：对话开始时，Agent 会看到可用技能及其描述的列表。
2. **激活 (Activation)**：如果某个技能看起来对任务有用，Agent 会读取完整的 `SKILL.md` 内容。
3. **执行 (Execution)**：Agent 在处理任务时遵循该技能的指令。

你不需要显式告诉 Agent 使用哪个技能——它会根据上下文自行决定。不过，如果你想确保使用某个技能，也可以直接通过名称提及它。

## 最佳实践

### 保持专注

每个技能应该只做好一件事。不要创建一个“全能”技能，而是为不同的任务创建独立的技能。

### 编写清晰的描述

描述是 Agent 判断是否使用技能的关键。请务必具体说明技能的作用以及它在什么时候有用。

### 将脚本视为黑盒

如果你的技能包含脚本，鼓励 Agent 先通过 `--help` 运行它们，而不是阅读整个源代码。这能让 Agent 的上下文始终专注于任务。

### 包含决策树

对于复杂的技能，可以添加一个章节来帮助 Agent 根据不同情况选择正确的方法。

## 示例：代码审查技能

这是一个帮助 Agent 进行代码审查的简单技能示例：

```markdown
---
name: code-review
description: 审查代码变更中的 Bug、风格问题和最佳实践。在审查 PR 或检查代码质量时使用。
---

# 代码审查技能 (Code Review Skill)

在审查代码时，请遵循以下步骤：

## 审查清单

1. **正确性**：代码是否实现了预期功能？
2. **边界情况**：是否处理了错误情况？
3. **风格**：是否符合项目约定？
4. **性能**：是否存在明显的效率低下？

## 如何提供反馈

- 具体说明需要更改的地方
- 解释原因，而不仅仅是“做什么”
- 尽可能提供替代方案
```
